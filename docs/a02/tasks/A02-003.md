## 1. Mục tiêu
Nâng cấp hệ thống xác thực JWT trên `FUNewsManagement_CoreAPI`, bổ sung mô hình cấp phát và làm mới Token qua endpoint `POST /api/auth/refresh` và bảng `RefreshToken` trong CSDL.

---

## 2. Điểm chạm mã nguồn
- `Controllers/AuthController.cs`
- `FUNews.BusinessLogic/Services/TokenService.cs` hoặc `AuthService.cs`
- `FUNews.BusinessLogic/DTOs/AuthDTOs.cs` (LoginResponse, RefreshTokenRequest, TokenPairResponse)
- `FUNews.DataAccess/Models/RefreshToken.cs`
- `FUNews.DataAccess/FUNewsDbContext.cs`

---

## 3. Các bước triển khai
1. Định nghĩa Entity `RefreshToken` và đăng ký vào `FUNewsDbContext`.
2. Tạo hàm sinh Refresh Token ngẫu nhiên bảo mật (Cryptographic RNG, độ dài 64 bytes base64).
3. Cập nhật `POST /api/auth/login`: Khi đăng nhập thành công, ngoài `accessToken` còn sinh thêm `refreshToken`, lưu bản ghi vào bảng `RefreshToken` và trả về cho client.
4. Xây dựng endpoint `POST /api/auth/refresh`:
   - Tiếp nhận `refreshToken` từ client.
   - Kiểm tra tính hợp lệ: Token có tồn tại không, đã hết hạn chưa (`ExpiresAt > DateTime.Now`), đã bị thu hồi chưa (`IsRevoked == false`).
   - Nếu hợp lệ: Đánh dấu thu hồi token cũ, sinh cặp `accessToken` + `refreshToken` mới, lưu token mới vào DB và trả về cho client (Token Rotation).
   - Nếu không hợp lệ: Trả về mã lỗi HTTP `401 Unauthorized`.
5. Xây dựng endpoint `POST /api/auth/logout`: Đánh dấu `IsRevoked = true` cho token hiện tại.

---

## 4. Tiêu chí hoàn thành (Acceptance Criteria)
- [ ] Endpoint `/api/auth/login` trả về cả `accessToken` và `refreshToken`.
- [ ] Endpoint `POST /api/auth/refresh` cấp cặp token mới thành công khi gửi refresh token hợp lệ.
- [ ] Thu hồi token cũ ngay khi vừa làm mới xong; từ chối nếu token cũ bị sử dụng lại.
