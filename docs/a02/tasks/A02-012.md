# Task A02-012 — Frontend: Xây Dựng Background Worker (HostedService 6h)

- **Trạng thái:** `TODO`
- **Phụ thuộc:** `A02-004`, `A02-008`
- **Hạng mục:** Frontend Web App

---

## 1. Mục tiêu
Xây dựng dịch vụ chạy ngầm `CacheRefreshWorker` kế thừa từ `BackgroundService` trong Frontend, tự động gọi các Web APIs định kỳ mỗi 6 giờ/lần để nạp dữ liệu danh mục, thẻ tin và các bài viết công khai vào bộ nhớ đệm hoặc file snapshot JSON cục bộ, chuẩn bị sẵn nguồn dữ liệu cho chế độ Offline Mode.

---

## 2. Điểm chạm mã nguồn
- `FUNews.Client.DataAccess/Services/CacheRefreshWorker.cs`
- `FUNews.Client.DataAccess/Services/OfflineStoreManager.cs`
- `Program.cs` (Frontend: đăng ký HostedService)

---

## 3. Các bước triển khai
1. Xây dựng dịch vụ quản lý lưu trữ `OfflineStoreManager`:
   - Hàm `SaveSnapshotAsync(categories, tags, articles, ct)`: Lưu dữ liệu dưới dạng JSON vào thư mục `App_Data/cache/snapshot.json` hoặc trong `IMemoryCache`.
   - Hàm `GetSnapshotAsync()`: Đọc dữ liệu từ file snapshot khi cần fallback.
2. Xây dựng `CacheRefreshWorker` kế thừa `BackgroundService`:
   - Tiêm phụ thuộc `IServiceProvider` và `ILogger`.
   - Thiết lập chu kỳ 6 giờ (`TimeSpan.FromHours(6)`). Có thể hỗ trợ cấu hình khoảng thời gian này trong `appsettings.json` để tiện kiểm thử ngắn hạn (ví dụ: 1 phút khi test).
   - Trong `ExecuteAsync`:
     - Chạy nạp dữ liệu ngay 1 lần khi ứng dụng vừa khởi động.
     - Sử dụng `PeriodicTimer` để thức dậy mỗi 6 giờ và gọi lại luồng làm mới dữ liệu.
     - Tạo DI Scope để phân giải `ICoreApiClient`.
     - Gọi các API đọc dữ liệu: Lấy Categories, Tags và Danh sách bài viết Active.
     - Lưu bản chụp vào `OfflineStoreManager`.
     - Bắt ngoại lệ và ghi log cẩn thận, không làm crash ứng dụng nếu API tạm thời không phản hồi.
3. Đăng ký dịch vụ trong `Program.cs`: `builder.Services.AddHostedService<CacheRefreshWorker>();`.

---

## 4. Tiêu chí hoàn thành (Acceptance Criteria)
- [ ] Worker khởi động mượt mà cùng Frontend, tự nạp dữ liệu cache ngay khi ứng dụng chạy.
- [ ] Dữ liệu được ghi vào file snapshot/bộ nhớ đệm thành công.
- [ ] Chu kỳ 6 giờ chạy ngầm hoàn toàn không gây chậm hoặc gián đoạn luồng giao diện của người dùng.
